# BG3 — special requirements and remaining integration work

Reviewed **4 November 2026** for Windows PC multiplayer. These are selected-mod requirements and researched installation routes, not a mandatory bundle or a compatibility guarantee. Modlane 0.3.14 prepares library content; actual BG3 deployment, tool installation, moves/restoration and launch remain locked. See [the preparation guide and tests](BG3_SUPPORT.md).

## Account control is still a required gate

[mod.io's support page](https://support.mod.io/hc/en-us/articles/10641317856655-How-do-I-link-my-Larian-account-to-a-mod-io-account) identifies [the linked-accounts page](https://mod.io/me/account#linked). The [activation guide](https://support.mod.io/hc/en-us/articles/10635137346831-How-do-I-activate-mod-io-in-Baldur-s-Gate-3) distinguishes the in-game sign-in from a website session. Use the supported in-game/account controls in a separately designated test setup, keep Steam online, and retain subscriptions/files. Modlane opens the account page only on the player's click; it does not log in, unlink accounts or edit/revoke game credentials.

Signing out/unlinking is a candidate control, not established prevention: [Larian describes anonymous limited modding access](https://baldursgate3.game/modding-privacy/), and remembered sessions, automatic re-authentication, startup downloads and save/lobby prompts still need controlled observations. The [generic mod.io logout API](https://docs.mod.io/restapi/docs/logout) requires the application's token and cache cleanup; it is not permission or a supported interface for Modlane to read/revoke BG3's credentials.

Account setup records only player observations, scoped to the inspected content and expiring after 24 hours. They never establish actual session state, unlock management/launch or export trusted compatibility evidence. No offline switch, service-DLL removal, blanket read-only directory or credential-cache deletion is used.

## Before enabling managed online play

1. Designate an isolated Windows game/user test environment and verify remembered-session sign-out/unlink behaviour across restarts, host/join/reconnect and mismatch prompts. Observe unwanted acquisitions/replacements while keeping multiplayer online. The working 167-mod collection is not the destructive test fixture.
2. Implement journalled holding-area moves/restoration outside all BG3 watched roots, including cross-volume copies, interruption recovery, disk-space checks, external edits and process guards. The current preview moves nothing; library copies are not this transaction system.
3. Implement correct Public/campaign configuration with exact base identities, preservation of unknown fields, selected module order and meaningful reset detection. Keep loose/native payload scopes separate and never equate an empty list with vanilla.
4. Integrate selected tool installation/current game-build support, fresh SE runtime evidence, save/settings preservation and rendering/native recipes. Prepare is distinct from installed/initialized.
5. Verify a fresh Trials campaign with exact files and two Windows PCs, then enable a supported scope and exact shared-preset reproduction. Record developer checks and player acceptance separately.
